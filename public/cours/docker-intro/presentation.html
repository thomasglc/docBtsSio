Docker

Qu'est-ce qu'un conteneur ?

Docker empaquette une application avec tout ce dont elle a besoin :

  • Le système de base
  • Les bibliothèques et dépendances
  • La configuration
  • Le code de l'application

Le tout dans une unité portable appelée conteneur

Conteneur vs Machine Virtuelle

Machine VirtuelleConteneur Docker
ContientOS complet + applicationApplication + bibliothèques
Démarrage1 à 2 minutesQuelques secondes
TaillePlusieurs GoQuelques dizaines de Mo

Un conteneur n'est pas une VM légère — c'est un processus isolé sur le noyau hôte

Les 3 concepts clés

1. L'Image

Définition

Un modèle immuable qui décrit ce que contiendra un conteneur.

Une image ne s'exécute pas directement — elle sert de base pour créer des conteneurs.

🍳 Analogie : la recette de cuisine

docker pull httpd # télécharger l'image Apache

2. Le Conteneur

Définition

Une instance en cours d'exécution d'une image.

On peut créer autant de conteneurs qu'on veut à partir de la même image.

🍽️ Analogie : le plat cuisiné

docker run httpd # créer et démarrer un conteneur

3. Le Registry

Définition

Un serveur qui stocke et distribue des images Docker.

Docker Hub est le registry public principal — des milliers d'images prêtes à l'emploi.

🛒 Analogie : le supermarché d'images

# hub.docker.com → httpd, mysql, wordpress…

Les commandes de base

Télécharger et lister des images

docker pull httpd # télécharger l'image depuis Docker Hub

docker images # lister toutes les images locales

Les images sont construites en couches — chaque ligne "Pull complete" est une couche. Elles se partagent entre images, ce qui économise de l'espace.

Lancer un conteneur

docker run httpd # au premier plan (bloque le terminal)

docker run -d httpd # en arrière-plan (détaché)

docker run -d --name web httpd # avec un nom fixe

  • -d → détaché, le terminal reste libre
  • --name → nom fixe plutôt qu'un nom aléatoire

Gérer les conteneurs

docker ps # conteneurs en cours d'exécution

docker ps -a # tous les conteneurs (même arrêtés)

docker stop web # arrêter (conserve le conteneur)

docker start web # redémarrer

docker rm web # supprimer définitivement

stop ≠ rm — Un conteneur arrêté conserve ses données. rm les supprime définitivement.

Réseau

Les conteneurs sont isolés

Par défaut, un conteneur n'est pas accessible depuis l'extérieur.

Sans mapping

Apache tourne sur le port 80 à l'intérieur du conteneur, mais personne ne peut y accéder

Avec mapping

On crée un "tunnel" entre un port de la machine hôte et le port du conteneur

Exposer un port

docker run -d -p 8080:80 --name web httpd

Port hôte

8080

Port de votre machine, accessible depuis le navigateur

Port conteneur

80

Port interne sur lequel Apache écoute

# Accessible via http://[IP-VM]:8080

Volumes

Attention aux données !

Tout ce qu'on écrit dans un conteneur…

docker exec -it web bash

echo "Bonjour" > /usr/local/apache2/htdocs/index.html

exit

⬇️

docker rm -f web # supprime le conteneur

Les données sont perdues pour toujours.

La solution : les volumes

Un volume existe en dehors du cycle de vie du conteneur.

  • Les données survivent à docker rm
  • Partageable entre plusieurs conteneurs
  • Géré par Docker dans /var/lib/docker/volumes/

docker run -d -p 8080:80 \

  -v mon-volume:/usr/local/apache2/htdocs \

  --name web httpd

Docker Compose

Pourquoi Docker Compose ?

Un site WordPress, c'est deux conteneurs :

🌐

WordPress

Le site web

🗄️

MySQL

La base de données

Gérer chaque conteneur à la main → compliqué. Compose centralise tout dans un seul fichier.

Le fichier docker-compose.yml

services:

  web:

    image: httpd

    ports:

      - "8080:80"

  mysql:

    image: mysql:8.0

    environment:

      MYSQL_ROOT_PASSWORD: secret

    volumes:

      - db_data:/var/lib/mysql

Une commande pour tout

docker compose up -d # démarrer tous les services

docker compose ps # état des services

docker compose logs -f # suivre les logs

docker compose down # tout arrêter et supprimer

Le réseau entre conteneurs est créé automatiquement — ils se trouvent par leur nom de service.
